# Projectile framework (P1-P5)

Design: `Docs/ProjectileDesign.md`; plan: `Docs/ProjectileImplementationPlan.md`. This document describes what the code does now.
A projectile is **not an entity** (no `PNStat`, no `PNBuffManager`), has **no collider**, and is independent of the skill that fired it.

## Parts
| Type | Role |
|---|---|
| `PNProjectileDefinition` | Registry entry (kind `projectile`, a `PNInstanceDefinition` in the shared `instances` registry; JSON entries sit in `extensions.project_n.instances` with the extra field `destroyable`): id, one concrete `PNProjectileInstance` implementation, a validated payload, `Derive`, `Settings<T>()` (payload parsed once per definition). |
| `PNProjectileLaunch` | Immutable data captured when a volley is fired: `PNCombatSource`, `PNPreparedDamage` (may be null), `PNSkillHitSnapshot` (may be null), required target layer mask, speed/scale/lifetime factors. `FromSource` reads the factors from the `projectile_speed/scale/lifetime` tags with `PNCombatSourceSnapshot.Calculate(1, tag)`. `projectile_damage` is a tag the damage step adds to the damage tags. |
| `PNProjectileSpawn` | Per projectile: scene, position, direction (normalized), optional initial target. |
| `PNProjectileInstance` | Base of an implementation. Author writes `Initialize(spawn)`, `Move(dt)` (update `Velocity`) and `OnContacts(contacts)`; defaults for the rest (`OnEnd`, `Cleanup`, `EnvironmentMask`, `Gravity`, `IsExpired`, `SubStepLimit`). The base integrates `position += (Velocity + External) * dt`, splits a tick into sub-steps, finds contacts, and exposes `Finish(reason)`. |
| `PNProjectileClock` | A standard `EveTimeScale` (minScale 0) on every projectile, advanced only by the manager. A time-stop modifier freezes movement, age and lifetime. The clock is advanced every tick even at scale 0, so a modifier whose owner vanished is reclaimed. |
| `PNProjectilePool` | Own pool per (definition, scene). Keeps idle objects in release order; reuse takes the newest, eviction destroys the oldest. Same `EveIPoolable` hooks as `EveEasyPooling` (`OnPoolGet` receives null). |
| `PNProjectileManager` | Independent service (does not touch `PNAreaManager`): re-entrancy-safe command queue, numbered handles, world lease per projectile, pools, global cap, cleanup on scene/world/session end. |
| `PNProjectileTargets` | Per-world candidate list (every loaded, ready, living entity with a hit box), refreshed each tick while projectiles fly in that world. Coarse filter only. |
| `PNProjectileGeometry` | Oriented-box (SAT) vs axis-aligned box test, closest point, segment distance. No allocation. |
| `PNProjectileProfile` | Platform limits: `MaxActive` (mobile 500, else 1000) and `MaxSubSteps` (4). Lives in `PNPlayConfig.Projectiles`; startup argument `--pn-projectile-cap=<n>`. Not content: mods cannot change it and it is not in the content hash. |

## Behavior
- **Create** (`manager.Create(launch, spawn)`) returns a receipt: `Created`, `Rejected` (closing/inactive session, world not runnable, or the cap reached with every object active), `Failed` (bad request, unknown id, invalid input, cleanup fault). Called from inside a hook it returns `Pending` and completes after the current command.
- **Cap**: total objects across all pools (active + idle) never exceed `MaxActive`. A new object at the cap destroys the idle object that has waited longest in any pool; if none is idle the request is rejected. A projectile never overwrites a running one.
- **Tick**: `clock.Advance(gameDelta)`; `dt = gameDelta * clock.Scale`; sub-steps = `ceil(step distance / smallest half extent)` clamped to `min(MaxSubSteps, SubStepLimit)`; each sub-step runs `Move`, integrates, then detects contacts and calls `OnContacts` when there are any.
- **Contacts**: environment = `PhysicsScene.BoxCast` along the sub-step in the world's own physics scene (the spawn scene when it is not a world), `QueryTriggerInteraction.Ignore`, mask from `EnvironmentMask` (default content: `Wall`; `Boundary` passes). A projectile that starts inside a collider is not stopped by it (BoxCast ignores initial overlaps). Targets = candidates on the launch layer mask whose box overlaps the oriented body box at the end of the sub-step (and at the start for the first sub-step). Each overlapping sub-step reports again, so an implementation that does not end sees a target repeatedly. `PNProjectileContact`: `Target`, `Point` (nearest point on the target box to the sub-step start), `Normal`, `Fraction` (approximate entry order: projection of the target center on the step; use it for sorting only). A hit volume other than the root non-trigger collider bounds is declared by implementing `PNIProjectileHitVolume` on the entity.
- **Ending**: `Finish(reason)` or `manager.End/Destroy(handle, reason, source[, bypass])` (`Destroy` honours the definition's `destroyable` flag, see "Team, source and destroyable"); `OnEnd` and `Cleanup` run, the object returns to the pool. `Snapshot()` lists running projectiles (position, heading, box, world, handle) for systems that scan or clear them; their geometry and filtering are the caller's.
- **Cleanup**: `SceneUnloaded`, `ReleaseWorld(world)` (wired in `PNGameSession` next to the Area manager through one combined `BeforeUnload` delegate), `Shutdown()` (session cleanup registered in `EveGameRuntime.BindSession`).

## Built-in implementation `project_n:directional` (`base:directional`)
Payload, every field required unless noted: `speed`, `acceleration`, `speedMin <= speed <= speedMax`, `life {mode: "Time"|"Distance", value > 0}` (exactly one), `volume {size:[x,y,z]}` (full box: x right, y up, z forward), `environmentMask` (layer names; `[]` = ignore the environment), `gravity` (optional `[x,y,z]` external velocity), `subSteps` (optional 1..16). Launch input takes no fields. Launch factors multiply speed (and its limits), body size, and the life value. It ends on time/distance or an environment hit; target contacts go to `OnTargets` (empty until the damage step). Mods derive projectiles from JSON (`extensions.project_n.projectiles: [{id, factoryId, data}]`, atomic with the batch) or write a new implementation.

## Hits, volleys and homing (P2-P3)
- **Hit path**: an implementation calls `ApplyHit(contact)`. It validates the target (ready, active, alive, same world), takes the launch's `PNPreparedDamage` and rolls the critical **per hit** (`snapshot.CreateDamage(prepared)`), calls `target.ReceiveDamage`, then runs the frozen `PNSkillHitSnapshot` with this projectile's own `PNSkillHitAdmission` and a detached `PNProjectileHitContext` (source and world from the launch, no live skill). `HitCount` is the PerHit index. The built-in implementations always call it; one that wants to carry buffs must too. Damage is fixed at launch: later modifier changes on the shooter, or the shooter dying/unloading, change nothing.
- **Directional hit rule**: `hitLimit` (required, > 0) hits end the projectile (`Hit`); `hitCooldown` (optional, projectile-clock seconds) lets the same target be hit again after it, otherwise each target is hit once. Targets in front of a wall (earlier along the step) are hit before the wall ends the projectile.
- **`project_n:create_projectile` Operation** (`base:` alias; needs a direction and a live skill, not `SourceIndependent`): payload `projectileId`, `input`, `count` 1..3, `spread` degrees (0..90, around the world up axis), optional `targetLayers` (ordered layer names added to the caster's own `TargetLayers`; the union must not be empty), optional `aimRadius` (> 0..1000: aim the volley at the nearest live target on those layers within that radius, planar, found with `manager.ResolveNearest`, and give it to every projectile as its initial target; no target = the context direction), optional `pitches` (one angle per projectile in volley order, -80..80 degrees, positive raises the nose; tilts about the horizontal axis perpendicular to the heading), optional `damage {value, canCrit, tags (exactly one damage type), iframeDuration?}`. It prepares the damage once for the volley (skill tags + `damage.tags` + `projectile_damage`), freezes the skill's OnHit effects when the context allows it (`context.CanFreezeOnHit`), reads the `projectile_*` factors from the source snapshot, and fires. Receipts per projectile are in `Results`; a full cap gives `Rejected` receipts (a short volley), a failed creation throws. **`project_n:projectile_action`** wraps it like `area_action` (start begins the action context so the OnHit plan can be frozen; `Results` stays readable after exit). An Operation run as an effect of a skill gets a context that cannot freeze, so it fires without the OnHit plan; use the Action for that.
- **`project_n:homing`** = directional plus `turnRate` (deg/s), `homeAfter`, `lostTarget` (`Reacquire` or `KeepHeading`), `searchRadius`, `searchInterval` (all required). Target from the spawn request or, if missing/lost and `Reacquire`, the nearest live target on the launch layers (`manager.FindNearest`, searched at most every `searchInterval` of the projectile clock). Validation, search and the target center are resolved once per manager tick; the turn happens every sub-step. `KeepHeading` with no initial target never homes.
- **Candidates**: membership of the per-world list is rebuilt every `PNProjectileProfile.TargetRefreshSeconds` (0.1 s; 0 = every tick); the boxes are re-read every tick and dead/unloaded entities are dropped at once. A spatial hash on XZ limits each projectile to nearby candidates. `FindNearest(world, position, radius, layerMask)` reads the same list (null until a projectile has flown in that world).

## Eve's Skill projectile and its test visual
`project_n:eve_skill_homing` (`base:eve_skill_homing`) is registered in code (`PNProjectileGameplayContent`): `project_n:homing` data with speed 7, size .175, life 3.5 s, turnRate 540, homeAfter .25, searchRadius 12, Reacquire, no gravity, implemented by `PNTrailHomingProjectile` (a `PNHomingProjectile` with a minimal visual). The visual (`PNProjectileTrail`) is a camera-facing quad head rolled along the heading on screen (`PNViewCamera.Current`, texture `Head` = `Romb3.png`) plus a `TrailRenderer` tail (texture `Trail` = `Trail6.png`, tapered width (.17), gold fade, view-aligned), built in code with the shader `Project_N/VFX/ProjectileTrail` and two texture references from `Resources/PNVfx/ProjectileTextures` (`PNProjectileTextureReferences`, pack textures referenced by GUID, never copied). It starts on the first LateUpdate after the pooled object is active, clears on end, and a stopped clock keeps the tail by extending the trail time (the tail pops when time resumes, not smooth); no launch or hit effects (P6). `manager.ResolveNearest(world, position, radius, mask)` is a launch-time one-shot query on a scratch list; it works before any projectile has flown in the world.

## Ground layer and time stop (P4-P5)
- Layer 13 **`Ground`** (`TagManager`) holds floor colliders. The floor object `Eve 3D Ground` of `PNHall`, `PNLobby` and `ErMode` is on it, and `Eve.prefab` `PNPlayerMove.groundLayers` is `Default | Ground` (it was `Default` only, so the probe would have lost the floor otherwise). A projectile reacts to the floor only when its `environmentMask` lists `Ground`; the default content mask stays `["Wall"]`. Other layers' collision matrix rows are unchanged (a new layer collides with everything by default).
- **TimeScale Area on projectiles**: `PNTimeScaleArea.PollProjectiles` (same poll as entities) asks `PNProjectileManager.QueryRunning` for running projectiles of the area's world inside the radius and, unless the area's layer rule excludes the `Projectile` layer, adds the same two modifiers an entity gets through the Buff (`Scale -reduction`, `MinScaleReduction +minimumReduction`) directly to each projectile clock with `owner = the area`. They stack with other areas, are removed when the projectile leaves, ends or the area ends, and are reclaimed if the area disappears. A stopped projectile does not age. The entity path through the Buff is unchanged.

## Target layers, source and destroyable (RulesVersion98; was team in 96)
- **What a projectile hits**: `PNProjectileLaunch.TargetLayers` (`PNTargetLayers`: `Mask` int for the scan, ordered `Order` kept for a later autotarget priority). `create_projectile` builds it as the shooter's `PNStat.TargetLayers` captured in `PNCombatSource.Capture` (`source.TargetLayers`) united with the payload's `targetLayers`; it is fixed at launch, so a Buff lease on the shooter later does not change a projectile already flying. There is no team: friendly fire is just a layer in the set. `SourceId` is the shooter's entity and survives the shooter dying or unloading.
- **Hit filter**: the contact scan keeps only candidates whose layer is in `TargetLayers.Mask`. `ApplyHit` also skips the shooter itself (`target.EntityId == Launch.SourceId`): not a hit, no damage, no OnHit, no `HitCount`, no `hitLimit` spent. Homing and `aimRadius` use the same mask; a projectile that needs another rule implements it itself.
- **Snapshots** (`manager.Get`, `Snapshot()`): `TargetLayers`, `SourceId` (the shooter's entity) and `Destroyable`, for skills that scan with `QueryRunning`; an enemy projectile is one whose `TargetLayers.Contains(PNLayers.Player)`.
- **Projectile objects have a layer**: every pool object (root and the children it was built with) is on layer `Projectile` (8), set once when the pool is created. Children an implementation adds at run time must set their own layer. Projectiles still have no collider, so this has no physics effect; it lets area masks, rendering culling and later mechanisms read one rule.
- **`destroyable`**: a property of the definition (default true), not of the implementation payload; JSON entries declare it beside `data` (`{"id":"mod:orb","factoryId":"base:directional","destroyable":false,"data":{...}}`, boolean only); `Derive(id, data, destroyable)` inherits the parent's value unless given. `manager.Destroy(handle, reason, source, bypass = false)` returns false and ends nothing when the definition is not destroyable and `bypass` is false; the skill decides `bypass`. `End`, `Finish` and every lifecycle end (expiry, hit, environment, owner/scene/world/session, Shutdown) are never blocked.
